# UXR-3 remaining facilities — baseline audit

12/10/2026. Scope authorized: 3B/3C/3D; 3A retained, no UXR-4. Blueprint §3–6, §9–12 and 3A implementation report inspected. Pre-existing uncommitted UXR-1/2/3A changes preserved; snapshots of touched owners and git status saved in `.audit-output/uxr3-baseline/` before edits.

Admin seats currently use AdminSeatContextRoute → generic AdminPortal form/table. Manager rooms/seats use ManagerPortal form-first lists. CinemaImageManager already owns requests with generations, current cinema, mutation locks and scoped API calls; redesign must retain those invariants and the component entry point. Admin cinemas is generic table/form. Existing Customer SeatMap embeds booking limits, booking availability and stage artwork: unsuitable for configuration reuse without changing Customer semantics. New SeatLayout/SeatInspector will be presentation components for staff only. Shared UXR-2A primitives and persistent ManagerCinemaStore/ManagerLayout remain the existing owners.

DB/SP reads: Admin and Manager Seat_List provide row/number/type/config status; no coordinates, aisle, pair geometry or history flags. Physical row grid is supported; filtered seats must retain their position. Seat update cannot move row/number; history type changes and future effective tickets are rejected by canonical SP. Delete rejects ticket history (Admin SEAT_HAS_TICKET_HISTORY, Manager SEAT_HAS_TICKETS). Room count is complete GHE count from Room_List; Room_Delete may deactivate history rather than remove it. Cinema_List has no room count; optional complete Room_List can supply accurate count when QL_PHONG exists. Cinema delete rejects dependent rooms/assignments/pricing/images, never cascades.

Gallery DTO: URL/MoTa/LaAnhDaiDien/ThuTuHienThi/TrangThai/NgayTao. URL create/update, cover, numeric display order and delete exist; no upload/storage service or image-kind field. Public gallery filters inactive images, so it cannot own admin management of hidden images. External image load failure does not prove server corruption.

Routes already exist; only feature ownership changes. Keep bookings and showtime/pricing screens/layout structure. Frontend services and backend/database files are read-only in this task. Live DB regression must independently verify an isolated test DB identity, use rollback, and never inherit prior PASS verdicts.
